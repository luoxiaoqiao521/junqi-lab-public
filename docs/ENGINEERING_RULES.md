# 工程纪律与体积预算

建议并入项目现有 AGENTS.md 与各任务书的验收项。目的：让"不写成屎山"靠检查强制，不靠自觉。
所有数字阈值都是起步值，可经用户批准后调整；调整要记入 docs/DECISIONS.md。

## 1. 依赖方向（单向，由检查脚本强制）

```
core      规则、状态、拓扑；零第三方依赖
  ↑
referee   持有真实状态，推进对局
observe   观察过滤（只依赖 core）
  ↑
belief    推断（只依赖 core、observe）
  ↑
strategy  分析（只依赖 core、observe、belief；不得引用 referee）
  ↑
app       命令行 / 界面
```

- `tools/`（Python）只通过命令行或绑定调用 core，不重写规则判断。
- `experiments/` 可以依赖任何模块；任何产品模块不得依赖它。
- "strategy 不得引用 referee"就是信息隔离的编译期保证：真实隐藏状态的类型在 strategy 里根本不可见。

## 2. 一条命令检查（`check`）

按 P0-00 报告的可用工具实现；缺少的工具记"未启用"，不为此安装。

1. 构建：警告视为错误。
2. 测试：单元测试、属性测试、固定种子的黄金日志哈希。
3. 依赖方向检查（扫描 include / import，违反第 1 节则失败）。
4. 代码体量检查（第 4 节阈值）。
5. 体积报告（第 6 节）。

任务回执必须附 `check` 的完整输出；未通过不得写 `machine_complete`。

## 3. 单一事实源

- 规则只在 core。棋子数量、等级序、点位表各只定义一处，其余引用或生成。
- 配置有 schema 和版本号；日志头记录配置哈希。
- Python 不重新实现布局合法性、走法合法性等判断，一律调用 core。
- 术语表 `docs/GLOSSARY.md`：座位 seat、手 ply、世界 world、观察 observation 等。一个概念只用一个名字。

## 4. 变更预算

- 每张任务书列出允许修改的目录；越界改动整单退回。
- 单文件不超过 500 行，单函数不超过 60 行；单任务新增产品代码不超过 800 行（测试不计）。
- 不新建"v2"并行实现：要么原地替换并删除旧实现，要么不做。
- 不留注释掉的代码、没有编号的 TODO、未被调用的函数。
- 不建 utils / common / misc 之类的杂物目录；公共代码必须有明确归属的模块。
- 接口变更写一条 `docs/DECISIONS.md`：背景、决定、影响，各一两句。

## 5. 重构安全网与定期清理

- 黄金日志：一组固定种子对局的日志哈希。重构前后必须一致；规则变更须显式更新并说明原因。
- 每 3 到 4 张功能任务后排 1 张清理任务：只做删除、合并、重命名。验收为黄金哈希不变、产品代码行数不增。
- 每张任务回执增加一项："本次删除了什么"。
- 版本控制：一张任务一个分支，验收后合并并打标签；被退回的任务整支丢弃，不在其上修补。

## 6. 体积预算

定义：发布包解压后的安装体积不超过 100 MB（硬上限），目标不超过 40 MB。
训练数据、用户棋谱、日志不计入，也不打进发布包。模型权重计入。

| 组成 | 预算 |
|---|---|
| core + 命令行 | ≤ 5 MB |
| 界面 | ≤ 20 MB |
| 内置数据（拓扑、布局先验表、默认配置） | ≤ 5 MB |
| 评价权重 / 小模型 | ≤ 10 MB |
| 余量 | 其余 |

预算是分配额，不是实测值；各项以 `check` 的体积报告为准。

规则：

- 发布包用文件白名单打包，不整目录拷贝；不含调试符号、测试、实验脚本、原始数据。
- 依赖台账 `docs/DEPENDENCIES.md`：名称、用途、许可证、带来的体积。新增依赖需批准。
- 发布产品不捆绑：Python 运行时、训练框架（PyTorch 等）、自带浏览器内核的界面框架。Python 只是开发与实验工具。
- 界面到对应阶段再选型，优先不自带浏览器内核的方案（系统 WebView2 或轻量原生界面），选型前先实测体积。
- 若将来需要神经网络：权重不超过 10 MB；推理用自写前向计算或小型运行库，体积先测后批。
- 运行库（MSVC）静态链接或随包附带，计入体积。
- `check` 输出各组成大小及与预算的差值；超预算即失败。
- 用户数据目录与安装目录分开；日志设保留上限或归档策略。

## 7. 串行实验回执和反馈预算

- 确定性离线实验复用 Windows 中台规则 junqi-serial。开票后在 ops/serial.json 声明票 ID、实际 HEAD 和步骤。现役入口 ops/CONTINUE.md 只给出当前下一票。正式开跑前检查源文件语法、工程门禁与任务范围；收尾审查声明的全部实验格、制品指纹和差异。
- 同一阶段保留一个机器回执和一份日志。仅通过阶段可发后继，旧事件忽略，重复事件复用回执。失败和中断保留失败点，修复后用新计划重新领取。中台的 done 仅指命令回执已交付，业务以本地 passed/blocked 为准。
- 扩量前写出这一轮需要区分的两个解释及后续决策。先量目标环境的胜、和、负、截断和配对不一致，再决定增加样本还是改反馈覆盖。保持部署对照冻结；诊断样本、开发筛选与最终确认分别分组。全和格照常保留，不作为该环境棋力等同的证据。
- 训练评价必须保留团队终局、信息边界、成本和相同冻结对照。动作价值应使用合法可见历史、实际轮转及成对续局验证。无法仅靠兼容底牌的几条手工样本确定身份概率。
- 不能裁决的项目记一次具体缺口、恢复条件与依据。复盘材料归档到 REPORTS，复用的约束才保留在本节。
- 批次结束时，根据普通对局、真实更新、保存重载与独立整局结果重新选择下一票。专项票登记受影响的路径、结果的实际消费者及结束条件。确定的正确性问题隔离相应入口或标签，其他已经核验的学习路径可继续用有界预算运行。
- 区分研究留存与发布晋升。比较连续学习与重置时，两组使用相同的新经验、表示、更新预算和独立评测。历史可重放失败作为回归依据，晋升使用新的确认来源。
- 对照教师增量时，回执记录制品指纹、教师实际调用和续算成本、可定向的标签数量以及优化器实际消费次数。把普通终局回报、教师偏好和仅供独立评审的结果分开。
